# Decision Log

Record fixes, workarounds, and intentional trade-offs here. A pre-commit hook (`scripts/hooks/pre-commit`) scaffolds a placeholder entry on any code commit that lacks one, and blocks commits whose decisions.md still contains an unfilled placeholder. Bypass (sparingly): `git commit --no-verify`.

Each entry follows this shape:

- **Symptom:** what the user / future reader experienced or saw.
- **Fix:** what was done.
- **Surfaces:** greppable tokens (file paths, symbol names) so future debugging can find this entry via `grep -r <token> docs/decisions.md`.
- **Watch:** what could go wrong next, or a related edge case. Use "None" if nothing applies.
- **Commit:** the commit SHA the Fix landed in (filled at commit time, can be "(pending)").

**Never include secrets, tokens, connection strings, or PII in entries — this file is committed.**

## 2026-09-05 — Per-page projection: every page true to its own scale bar (Stage 9B)
- Symptom: `validate` failed `scale-consistency` on any wide atlas — worst footprint error 0.695% against a 0.5% tolerance for the ~100 km Lincoln→Omaha cover grid at 1:100,000. Reproduced on a plain `--bbox` of the same extent, so it predated the locations work.
- Root cause (measured, not assumed): NOT transverse-Mercator scale distortion, which is only ~0.002% at these distances. `buildPageGrid` projected the whole extent through ONE projector centred on the extent, and away from that central meridian **meridian convergence** (γ ≈ Δλ·sin φ) rotates each page rectangle relative to the lat/lng axes. `AtlasPage.bbox` is axis-aligned, so the box that contains the rotated rectangle inflates by roughly `(W·cos γ + H·sin γ)/W`. A diagnostic sweep at 1:100,000 on Letter measured the error growing linearly with distance from the central meridian: 0.173% at 0 km, 0.363% at 20 km, 0.723% at 40 km, 1.082% at 60 km. Location pages never showed it because `buildLocationPage` already built its own projector per page.
- Fix: new `pageBBoxAround(center, halfW, halfH)` in `projection.ts` — builds the projector **about that page's own centre** and returns the AABB. `buildPageGrid` still lays page centres out on one shared lattice (so spacing and `overlap` stay exact) but derives each page's bbox from its own centre; `buildRouteAtlas` does the same for `R#` corridor pages, which run furthest off any one meridian; `buildLocationPage` now shares the helper. Measured after: a flat 0.173%–0.175% wherever the page sits, independent of extent width. Also removed the duplicated `planeRectToBBox` from both `grid.ts` and `route.ts`.
- Trade-off (deliberate): adjacent pages no longer share exactly coincident bbox edges — they overlap/gap by that same fraction of a page (~0.17%, ~30 m at 1:100,000). Page-to-page continuity is carried by the `neighbors` ids, not by geometric coincidence, whereas the scale bar is a promise about ground truth on the printed sheet; per-page truth is the one worth keeping. The residual 0.173% is the unavoidable box-around-a-curved-quad term and would only go away by giving `AtlasPage` a rotated footprint instead of an AABB.
- Verified: new `scale-fidelity.test.ts` (4 tests) pins that a wide grid validates, that the worst error does not grow with extent width (a ~250 km grid is within 0.05% of a narrow one), that long-route corridor pages stay true, and that location pages hold at high latitude / far longitudes. atlas-core 59, map-sources 29, render-cli 40, worker 6; typecheck clean. And `pdf-client` dispatches page furniture off the id *prefix* — `page.id.startsWith("L")` stamps a location pin through the centre of the page and `startsWith("R")` draws a corridor route over it — so a plain grid page got a pin marking a location that is not there.
- Fix: reserve `L` and `R` out of the grid row alphabet (`ROW_LETTERS`, 24 letters), making row labels bijective base-24. A generated label can no longer contain either letter in **any** position, so the three namespaces are provably disjoint at every grid size and the `startsWith` dispatch in `pdf-client` is sound rather than accidentally-true-for-small-grids. Chosen over prefixing grid ids (`G-A1`) because the id is printed on the page and cited in neighbour/continuation references — "M4" still reads as a map-book reference; "G-A4" does not.
- Blast radius, checked: the only shift is that Z is now row 23 and AA row 24 (was 25/26). `data/fixtures/sample-atlas.json` is a 2x2 grid (rows A and B), so the golden fixture and its test are untouched — confirmed by running them. Nothing anywhere parses a page id back into row/column, so no reader needed changing.
- Tests: `grid.test.ts` asserts no label in rows 0..1999 starts with (or contains) L or R, and that labels stay injective across a 60x12 grid. Both fail on the old code with "row 11 produced L1".
- Surfaces: packages/atlas-core/src/grid.ts, ROW_LETTERS, columnLetters, pageLabel, packages/atlas-core/src/grid.test.ts, packages/pdf-client/src/AtlasDocument.tsx
- Watch: the reservation is a contract between `atlas-core` and `pdf-client`. Adding L or R back to `ROW_LETTERS`, or adding a third id namespace whose prefix letter is still in the alphabet, re-opens both failures at once.

## 2026-09-09 — Tile fetches get a UA, a timeout, retries and a concurrency cap; a mostly-blank panel now fails the render
- Symptom (silent blank): a failed tile became parchment and `renderMapPanel` returned success anyway, so a total upstream outage produced an atlas of empty parchment pages and HTTP 200. The one code path that could have caught it — `render-cli`'s try/catch, which already names the page and which the worker classifies as a 502 — was never reached, because nothing threw.
- Fix + the threshold, chosen deliberately: reject a panel when **more than 10%** of its tiles produced no pixels. Not zero, because raster pyramids have genuine holes — USGS topo has no tiles past the CONUS coverage edge, so a page clipping the coast legitimately 404s a few tiles, and failing that render would break a valid request to guard against a defect it does not have; those gaps already flatten onto the parchment background. Not lenient, because at ~35 tiles per letter page 10% tolerates three absent tiles (a coverage edge) while rejecting a missing row, a throttling source or an outage — none of which is a map anyone should print and navigate from. Configurable via `maxFailedTileFraction`. Tolerated holes are no longer silent either: `MapPanel` reports `tilesRequested`/`tilesMissing` and `render-cli` prints a per-page WARNING.
- Symptom (unbounded fetch): `fetchTile` was a bare `fetch(url)` — no User-Agent, no timeout, no retry — and the panel opened every tile at once with `Promise.all`. Measured 30 concurrent sockets for one page in a test.
- Fix: `TILE_USER_AGENT = "JourneyBook/1.0 (atlas basemap tiles)"`, the same `JourneyBook/1.0 (<what for>)` shape as the Overpass and Nominatim clients in `DependencyInjection.cs` — this is the same class of bug as the Overpass `406 Not Acceptable` that silently returned `[]` from every landmark import until a UA was added. Plus `AbortSignal.timeout` (10 s per attempt; Node's fetch has no default, so one hung source stalled a whole render forever), 3 attempts with 200/400 ms backoff, and a 6-way concurrency cap (`mapWithConcurrency`, conventional per-host browser limit). Retries are keyed on transience: 408/425/429/5xx retry, 404/403 do not — an absent tile is an answer, and retrying a coverage edge twice more just triples the load on it.
- Tests: `panel.test.ts` now serves **real 256x256 PNG tile bytes** instead of stubbing every fetch to 404. The old stub meant the encoding tests exercised the encode path over a panel with no map in it — they were asserting the exact failure mode this change had to detect. Nine tests fail against the old code, including "expected 30 to be less than or equal to 3" (concurrency) and two "promise resolved instead of rejecting" (the blank-panel success).
- Surfaces: packages/map-sources/src/panel.ts, TILE_USER_AGENT, DEFAULT_TILE_TIMEOUT_MS, DEFAULT_TILE_ATTEMPTS, DEFAULT_TILE_CONCURRENCY, DEFAULT_MAX_FAILED_TILE_FRACTION, fetchTile, isRetryableStatus, mapWithConcurrency, renderMapPanel, packages/map-sources/src/panel.test.ts, packages/render-cli/src/render.ts
- Watch: the threshold is per **page**, not per atlas — 30 pages each losing 9% of their tiles all pass while the atlas as a whole is badly holed. The disk cache is consulted before the fetch, so a cache full of good tiles masks a dead source entirely (by design: that is what the cache is for).
